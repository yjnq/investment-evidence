# 知序：投资事件情报与证据时间线

一个可实际操作的并购重组事件研究原型：把材料中的说法拆成可核验陈述，归入同一交易，保留每次判断与依据的变化。

- **产品 URL**：<https://investment-evidence-production.up.railway.app/>
- **源码仓库**：<https://github.com/yjnq/investment-evidence>
- **106秒演示视频**：<https://investment-evidence-production.up.railway.app/demo.mp4>（中文字幕、无音轨）
- **自动演示入口**：<https://investment-evidence-production.up.railway.app/?demo=1>
- **公网验收记录**：[public-acceptance.json](docs/public-acceptance.json)

页面可直接浏览。导入、检索、关注等写入操作需要在右上角“设置写入口令”输入随笔试附件单独提供的评审口令。这里不需要填写模型 API 密钥。当前是共享的单用户评审空间，没有多租户账户系统。

## 目标用户与任务

面向跟踪关注公司重大事项的个人研究者和轻量投研用户，回答：当前找到的最早来源是什么、哪些说法有直接证据、哪些仍未确认、新材料究竟改变了什么、过去为何作出当时的判断。

首版只聚焦并购重组。系统管理事件事实与证据，不预测股价，不提供买卖指令。

## 评审建议操作路径

1. 打开“国泰君安—海通证券”真实事件，查看“结论与证据”。区分“核准吸收合并”与“交易已经完成”。
2. 打开“来源材料”，查看证监会原网页链接、引用片段，以及发生、披露、导入、来源更新时间。
3. 打开“版本时间线”，比较监管批复版本和后续补入的历史候选片段。旧材料虽然更早披露，但不能把已有审批阶段倒退。
4. 打开V1，再返回当前版本。历史快照只包含当时已取得的证据。
5. 查看“示例科技”构造测试案例，演示部分否认、10亿元更正为9亿元、预测到期失效；查看具体陈述的状态差异和通知。
6. 输入评审口令后，可在“接入新材料”导入单项交易原文，或用iFinD检索公告候选。重复提交已成功材料不会新增版本和通知。

**真实与构造数据严格区分**：示例科技、示例芯片、示例软件都是虚构测试数据。测试沙盒使用人工标注夹具，不调用AI。真实材料导入则实际调用GPT兼容接口，不返回固定预置答案。

## 核心设计

- 材料、陈述、事件、历史版本、任务和通知分别建模。一个材料可抽取多条独立说法。
- 陈述类型（事实性陈述、观点、推测、传闻）与核验状态分开，事实性陈述不自动等于已确认事实。
- 来源权重以一手/转述、是否人工核对、来源身份和适用范围解释；不输出未经校准的可信度百分比，转载不重复计票。
- 模型选择候选事件ID时必须提供原文依据，并复用交易标识；程序再次核对主体、对象、交易批次与引用。不同交易保持分开，相似档案提示复核。
- 更正与否认只作用于对应命题；时点不同不自动构成矛盾。过期只改变特定时效性陈述，不代表陈述虚假或业务终止。
- 版本保存完整快照，展示新增陈述、核验状态和业务阶段差异；重要版本变化对已关注事件产生去重通知。
- 未知日期留空，不把抓取时间当作首次披露时间；“最早来源”仅表示当前已获取材料中的最早已知披露。

## AI角色与程序边界

AI负责从新材料抽取主体、对象、交易身份、陈述、类型、引用及证据关系，并提出与已有事件的匹配判断。服务端校验结构、实体出现性、逐字引用、候选存在性及事件身份，再执行状态规则、事务、版本和通知。

模型使用用户提供的第三方OpenAI兼容服务，配置名称为 `gpt-5.6-sol`；不能独立证明供应商底层模型身份。已完成真实调用验证。AI没有任意网页抓取、交易或工具执行权限，材料内的指令仅作为数据处理。模型失败时保留材料和失败任务，不发布模拟结果。

引用存在性校验不能代替完整语义核验，模型仍可能漏掉条件或误分类。演示关键数字与条件的对照见 [AI使用与验证](docs/AI使用与验证.md) 和 [真实案例核验](docs/真实案例核验.md)。

## 数据使用与溯源

- **权威材料**：中国证监会证监许可〔2025〕96号的公开条款节选，记录原网页URL、出处、数字、条件和时间语义。该材料证明核准与注册申请获同意，不证明交易完成或资金到账。
- **iFinD**：在线公告候选片段，可能包含截断与解释性文字，不能直接当作逐字公告原文。无原始URL时明确标注待核验。上游日期保留来源边界，查询结果为空不代表事件不存在。
- **扶摇**：此前完成接入能力验证；本产品未展示扶摇行情/财务背景卡片，不把“接口已验证”写成“产品已实现”。
- **构造材料**：仅用于复现真实案例未覆盖的否认、更正、过期及相似交易边界，界面明确标识。

仅保留本演示需要的节选与引用。不提供上游全文批量再分发。

## 技术与本地运行

Next.js 16、React 19、TypeScript、Zod、Drizzle、PostgreSQL。云端使用托管PostgreSQL；本地无数据库URL时使用磁盘PGlite，数据在被Git忽略的 `.data/evidence`。

```bash
npm ci
cp .env.example .env.local
npm run dev
```

打开 <http://127.0.0.1:3000>。可先使用无需模型的构造测试沙盒。真实导入需在服务端配置：

```dotenv
MODEL_BASE_URL=https://供应商接口/v1
MODEL_NAME=模型名称
MODEL_API_KEY=密钥
IFIND_AUTH_TOKEN=iFinD密钥
```

也支持用 `OPENCODE_CONFIG_PATH`、`IFIND_CONFIG_PATH` 指向已有本机配置文件，仅供本地开发；云端必须使用私密环境变量。生产必需 `DATABASE_URL` 和 `APP_ACCESS_TOKEN`。任何密钥都不能使用 `NEXT_PUBLIC_` 前缀或提交Git。

```bash
npm test
npm run typecheck
npm run build
npm start
```

Railway使用Dockerfile、GitHub main自动部署、CI门槛和 `/api/workspace` 健康检查。可用唯一 `CLOUD_SMOKE_RUN` 批次运行一次性云端验收；结果存于 `verification_runs`，相同批次不重复调用模型。

## 已知边界与未做事项

- 首版一次处理一项并购交易；没有一文多事件拆分、全市场扫描、研报全文/OCR或自动定时抓取。
- 未实现完整别名知识库、人工拆分台或多租户账户隔离。相同双方的不同交易仍需复核；模型判断可能漏合并或误合并。
- 来源核对是操作者声明，不是平台自动认证。权威来源也可能更正。
- 历史与陈述存为事件JSON快照；全工作空间事务串行化适合小型演示，没有大规模并发性能承诺。
- 限流为单进程全局20次写入/分钟。评审口令应单独分享，页面刷新后需重新输入。
- 过期检查为手动触发，任务中断通过重试恢复；没有独立后台任务队列。
- 没有15–20对真实交易的广泛人工标注评测，也没有自动交易、收益保证或股价因果推断。
- 线上服务使用试用资源，其可用期限和余额应在正式提交时确认。URL可用不等于长期商业SLA。

演示中的真实事件采用历史材料。页面状态仅反映已收录证据，不是截至今天的全市场最新进展；录制时的材料、版本和通知计数可能因评审操作继续变化。
