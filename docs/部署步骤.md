# GitHub + Railway + PostgreSQL 部署步骤

GitHub 存源码，Railway 运行 Node 服务与数据库。GitHub Pages 只能部署静态文件，不能运行本项目的 API 与模型调用。

1. GitHub 右上角 `+ → New repository`，名称 `investment-evidence`，初期 Private，不初始化 README。复制 `https://github.com/<用户名>/investment-evidence`。
2. 本地检查 `.gitignore`，确保 `.env.local`、`.data`、个人凭据不被提交。只提交产品源码和允许分享的核验资料；iFinD 原始候选响应不需要公开。
3. 将项目推送到该仓库。不要将模型密钥放在 git remote URL。
4. Railway 创建项目，选择从 GitHub 部署。添加 PostgreSQL 服务，将其 `DATABASE_URL` 引用给 Web 服务。
5. Web 服务配置 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`、`APP_ACCESS_TOKEN`。这些变量只在平台的私密环境变量设置中输入，不能放在仓库或浏览器代码。
6. 不配置本地 `OPENCODE_CONFIG_PATH`，云端访问不到个人电脑的配置文件。优先使用模型平台的 HTTPS 地址；当前本机供应商配置为 HTTP，正式部署前应向供应商确认 HTTPS 入口。
7. 仓库内 Dockerfile 与 railway.json 已准备。部署后生成公共域名；将域名填写为 `APP_ORIGIN=https://...` 并重启。
8. 用外部浏览器核验页面、数据库、模型出站网络、引用、去重、通知、刷新及重启后的持久化。配置成功不等于云端验收通过。
9. 将源码仓库阅读权限授予评审，或仅在清理确认后公开。提交产品 URL、仓库 URL、视频及实际测试记录。

尚未执行任何云平台登录、收费资源创建或公开部署。Docker 配置已编写，本机无 Docker 可执行文件，镜像构建未实测。当前模型供应商并非官方 OpenAI API，兼容程度以真实接口测试为准。
